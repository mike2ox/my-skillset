$ARGUMENTS 의 관계도를 만듭니다. 아래 순서를 지킵니다.

이 스킬의 목적은 **그림을 빨리 그리는 것이 아니라, 틀린 그림을 발행하지 않는 것**입니다.
관계도는 한 번 만들어지면 팀이 사실로 믿고 인용하므로, 조사보다 검증에 무게를 둡니다.

## 1단계 — 조사

`repo-cartographer` 서브에이전트가 있으면 위임하고, 없으면 직접 수행합니다.
서버·프론트처럼 리포가 둘 이상 걸리면 **리포마다 하나씩 병렬로** 띄웁니다.

조사 전에 반드시:

- 리포마다 `git fetch origin` 후 개발 브랜치를 `git ls-remote --heads origin`으로 확인하고
  (`development` → `develop` → `dev`, **정확히 일치하는 이름**) 그 기준으로 읽습니다.
  로컬 HEAD로 조사하면 이미 사라진 코드나 남의 미머지 변경을 사실로 보고하게 됩니다.
- 여러 리포에 걸친 주제는 **양쪽을 각각 원격 기준으로 확인**합니다. 한쪽을 보고 반대쪽을
  추론하지 않습니다.

조사할 때:

- 스키마 → 리졸버 → 서비스 → 리포지토리 순으로 내려가며 **쓰기 경로를 끝까지** 읽습니다.
  컬럼 주석이나 필드 이름이 아니라 실제 create/update 호출부가 근거입니다.
- **저장된 값과 조회 시 계산되는 값을 구분**합니다. 계산되는 필드는 그렇다고 명시합니다.
- 권한 게이트가 리졸버에 있다고 가정하지 않습니다. 서비스 층에만 있는 경우가 흔합니다.

산출물은 다음 형식입니다.

```
### 엔티티
- `모델명` (테이블명) — 한 줄 역할 — 파일:줄
### 관계
- A → B: 카디널리티, 생성 시점, 파일:줄
### 진입점
- 라우트/쿼리 → 읽는 엔티티, 권한 게이트 위치, 파일:줄
### 확신 못 한 것
- 근거가 약한 항목. 없으면 "없음"이라고 적습니다. 비워두지 않습니다.
```

## 2단계 — 반증

1단계 결과에서 **부재 주장("X가 없다")과 불변식 주장("항상/절대 ~한다")만** 골라
검증합니다. 전부 검증하지 않습니다 — 비싸고, 실제로 뒤집히는 것은 이 둘입니다.
나머지 항목은 `파일:줄`이 곧 검증입니다.

`claim-falsifier` 서브에이전트가 있으면 주장 하나당 하나씩 위임하고, 없으면 직접 합니다.
직접 할 때도 **깨는 것이 목표**입니다. 지지 증거를 찾은 것은 아직 안 깬 것일 뿐입니다.

부재 주장은 최소 네 갈래로 찾습니다. 하나라도 걸리면 주장은 거짓입니다.

1. 정확한 식별자 (대소문자 무시)
2. 어간·복수형·접두사 변형 (`revenue` / `getRevenue` / `revenues`)
3. 생성물·스키마 파일 (`*.generated.*`, `schema.graphqls`, 마이그레이션)
4. 다른 이름의 같은 개념 (한국어 용어, 축약어, `*Legacy` / `*V1` 같은 구명칭)

그리고 **탐색 범위 자체를 의심**합니다 — 워크트리·다른 리포·제외 디렉터리를 빼먹지 않았는지.

## 3단계 — 사용자 확인

그리기 전에 **노드 목록과 "이 그림이 말할 한 문장"을 먼저 보여주고 동의를 받습니다.**
좌표를 다 잡은 뒤에 범위가 바뀌면 도면을 처음부터 다시 짜야 합니다.

## 4단계 — 작도

`diagram-author` 서브에이전트가 있으면 위임합니다. 없으면 `artifact-design`과
`artifact-diagramming` 스킬을 먼저 읽고 직접 씁니다. **두 스킬을 건너뛰지 않습니다** —
팔레트·타이포·라이트/다크 토큰 규칙이 거기에 있습니다.

- 색은 **의미가 있을 때만** 씁니다. 축이 둘이면 색이 둘, 조회 경로는 점선.
  장식으로 색을 늘리지 않습니다.
- 화살표에 라벨을 답니다. 라벨 없는 화살표는 "어떻게든 관련됨"이라는 뜻이라 정보가 아닙니다.
- 박스 안에는 이름·테이블명·한 줄 역할까지만. 설명 문장은 figcaption으로 뺍니다.
- 좌표를 그리드에 맞추고 **겹침을 직접 계산해 확인**합니다. "괜찮겠지"로 넘어가지 않습니다.

파일은 스크래치패드에 씁니다. 프로젝트 디렉터리를 더럽히지 않습니다.

## 5단계 — 발행

`Artifact` 도구로 발행합니다.

- `<title>`은 짧은 고유명사구. 설명을 덧붙이지 않습니다.
- favicon은 한 번 정하면 **갱신 때 바꾸지 않습니다.** 사용자는 탭 아이콘으로 찾습니다.
- 갱신은 **같은 파일 경로로 재발행**합니다. 새 경로는 새 URL이 됩니다.

## 보고할 때

- 모든 판정에 `파일:줄`을 붙입니다. 붙일 수 없는 것은 "확인 못 함"으로 적습니다.
- **서브에이전트 보고를 그대로 옮기지 않습니다.** 2차 정보입니다. 인용할 근거는
  직접 한 번 확인하고 옮깁니다.
- 2단계에서 뒤집힌 주장이 있으면 조용히 고치지 말고 **무엇이 뒤집혔는지 말합니다.**
