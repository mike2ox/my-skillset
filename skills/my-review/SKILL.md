코드 리뷰 피드백을 분석하고 개선사항을 적용합니다.

`$ARGUMENTS` 맨 앞의 선택적 `--output <파일-경로>`를 먼저 처리하고 제거한 나머지를 `REVIEW_CONTENT`로 사용합니다. 공백이 있는 경로는 인용합니다.

## 출력 경로 옵션

- `--output`은 **파일 경로**만 받습니다. 상대 경로는 현재 프로젝트 디렉터리 기준으로 해석하며, 디렉터리만 넘기면 올바른 파일 경로를 AskUserQuestion으로 다시 받습니다.
- `--output`이 있으면 3단계의 피드백 요약을 그 정확한 경로에 저장합니다. 상위 디렉터리가 없으면 임의로 만들지 말고, 생성 / 다른 경로 지정 / 저장 취소 중 하나를 AskUserQuestion으로 묻습니다.
- 지정한 파일이 이미 있으면 자동으로 덮어쓰지 말고, 덮어쓰기 / 다른 파일 경로 / 저장 취소 중 하나를 AskUserQuestion으로 묻습니다.
- `--output`이 없을 때는 아래의 기존 `docs/review/` 기본 저장 규칙과 파일명 규칙을 그대로 적용합니다.

리뷰 내용: `$REVIEW_CONTENT`

## 1단계: 피드백 분류 분석 (Agent 위임)

subagent_type을 code-reviewer로 지정하여 Agent tool을 호출하세요. 파라미터:
- description: "리뷰 피드백 분류 및 영향 범위 분석"
- prompt: 아래 내용 전달 (리뷰 내용 포함)

---
아래 코드 리뷰 피드백을 분석하여 수정 항목을 분류하고 영향 범위를 파악합니다.

리뷰 내용:
$REVIEW_CONTENT

수행할 작업:
1. 관련 파일을 읽어 현재 코드 상태를 파악합니다
2. 각 피드백 항목을 아래 기준으로 분류합니다:
   - 필수 수정 (버그, 보안, 타입 오류, 데이터 손실 위험)
   - 권장 개선 (구조, 가독성, 성능)
   - 선택적 제안 (스타일, 미래 개선)
3. 각 항목에 대해 수정 대상 파일 경로와 라인 번호를 특정합니다
4. 파생 영향이 있는 파일도 파악합니다
5. **피드백이 지적만 하고 해법을 안 준 항목**은 구체적인 수정 방향을 함께 제안합니다
6. **리뷰어가 현재 코드를 오해한 것으로 보이는 항목**은 그렇게 표시하고 근거(파일:라인)를 답니다

코드 수정은 하지 않습니다. 분류 결과와 수정 계획만 반환합니다.
---

## 2단계: 수정 적용 (직접 실행)

에이전트 분류 결과를 바탕으로:
1. 필수 수정부터 순서대로 적용
2. 각 수정 후 타입 오류 확인
3. 완료 후 적용 항목과 미적용 항목 요약

### 반영 원칙

- **필수 항목은 협상 대상이 아닙니다.** 동의하지 않더라도 일단 적용하거나, 적용하지 않을 근거를 코드로 제시합니다.
- **리뷰어 취향과 실제 문제를 구분합니다.** "내가 짰다면 이렇게 안 했을 것"은 수정 사유가 아닙니다. 코드 건강이 나아지는지가 기준입니다.
- **범위를 넘는 피드백은 분리합니다.** 이번 변경과 무관한 개선 요청은 그 자리에서 고치지 말고 "별도 작업" 항목으로 기록한 뒤 `/my-iterate`에 넘깁니다.
- **미적용 항목은 반드시 이유를 남깁니다.** 조용히 건너뛰지 않습니다.

### 이견이 있을 때

리뷰어 의견에 동의하지 않으면 아래 순서로 판단합니다:

1. 객관적 근거(측정값, 명세, 문서)가 있는가 → 근거를 따른다
2. 프로젝트에 확립된 관례가 있는가 → 관례를 따른다
3. 둘 다 없는 취향 차이인가 → 리뷰어 의견을 따르되, 판단 근거를 review 문서에 남긴다

## 3단계: 피드백 요약 저장

수정 완료 후 `--output`이 있으면 위에서 확정한 파일 경로에 피드백 요약을 생성합니다. 없으면 `docs/review/YYYY-MM-DD-{브랜치명}.md` 파일을 생성합니다.
기본 저장일 때만 `docs/review/` 디렉토리가 없으면 먼저 생성합니다.

파일 형식:
```markdown
# 코드 리뷰 피드백 — {브랜치명} ({날짜})

## 원본 피드백
{$REVIEW_CONTENT 전체}

## 분류 결과

### 필수 수정
- 항목별 내용, 적용 여부

### 권장 개선
- 항목별 내용, 적용 여부

### 선택적 제안
- 항목별 내용, 적용 여부 및 미적용 이유

### 범위 밖으로 분리한 항목
- 항목별 내용 및 후속 처리 방법 (없으면 섹션 삭제)

## 적용된 변경 파일
- 파일 경로: 변경 내용 한 줄 요약

## 판단 기록
- 리뷰어 의견과 다르게 처리한 항목이 있으면 그 근거 (없으면 섹션 삭제)
```

저장 완료 후 `/my-iterate`로 다음 개선 작업을 분해하거나, `/my-commit`으로 커밋하세요.
